## PART 1. 랜딩페이지 카피

### 헤드라인
**오늘 5경기, 뭐 볼지 1초 만에.**
KBO 전 경기를 **꿀잼지수(0~100)**로 점수 매겨 "오늘 이거 봐" 한 경기를 골라줍니다.

### 서브 카피
일정·순위는 네이버에도 있습니다. 우리가 주는 건 **"오늘 이 경기가 왜 볼 만한가"** 입니다.
경기마다 꿀잼지수 + **한 줄 이유** + **관전포인트 3개**. 감으로 고르거나 커뮤니티 여론 뒤지지 않아도 됩니다.

### 핵심 3줄
- ⚾ **꿀잼지수** — 순위 싸움·최근 폼·맞대결·선발 매치업 등을 규칙으로 합산한 0~100 점수. AI 환각 없음, 계산식이 일관됩니다.
- 💬 **한 줄 이유 + 관전포인트** — "왜 재밌는지"를 사람이 읽는 문장으로. "공동 5위 마지노선 한 판" 같은 맥락까지.
- 📱 **로그인·서버 없음** — 깔고 응원팀만 고르면 끝. 데이터 파이프라인이 깨져도 마지막 캐시를 보여주고 앱은 안 죽습니다.

### CTA
**무료. 광고 없음. 응원팀 고르고 바로 오늘 경기 보기.**

## PART 2. 세일즈 미팅 / 제품 상세

### 우리가 푸는 문제
코어 팬은 매일 5경기를 다 못 봅니다. 퇴근 후 하나만 고를 때, 네이버 스포츠는 일정·순위는 주지만 **"오늘 이 경기가 왜 볼 만한지"는 안 알려줍니다.** 그래서 감으로 고르거나 엠팍 여론에 의존하고, 다음 날 다른 경기의 끝내기·역전 하이라이트를 보고 "이걸 놓쳤네" 후회합니다. 우리는 그 **관전 의사결정 비용을 0에 가깝게** 만듭니다.

### 작동 방식
1. **온보딩(최초 1회)** — 응원팀 선택(팀명+대표색 그리드), 로컬 저장. 회원가입 없음.
2. **오늘경기 탭** — 최고 꿀잼 경기를 히어로로 최상단에, 나머지는 꿀잼 높은 순으로(시간·구장·지수).
3. **경기 상세** — 꿀잼지수 / 한 줄 예측 / 관전포인트 3개 / 선발 매치업(이름·ERA·승패). 종료 경기는 승·패 투수까지 표시.
4. **내 팀 탭** — 다음 경기·순위·최근 결과를 피드형으로.
5. **설정** — 응원팀 변경 · 데이터 갱신시각 · 앱 정보.

### 꿀잼지수가 믿을 만한 이유
- **규칙 기반 6요소 가중합 + 로지스틱 보정.** 블랙박스 AI가 아니라 일관된 공식이라, 같은 상황이면 같은 점수가 나옵니다.
- 순위 임팩트(공동순위 마지노선 등), 최근 폼(무승부 반영), 맞대결, 선발 매치업, 박빙 기대치 등을 반영.
- 한 줄 이유는 규칙 기반 문구라 **틀린 헛소리를 지어내지 않습니다.**

### 데이터 신뢰성
- KBO 공식 데이터를 정적 JSON 파이프라인으로 수집(GitHub Actions, 5분 주기 외부 cron 트리거).
- 선발 ERA는 규정 미달 투수도 개별 조회로 커버. 종료 경기 승/패 투수 표시.
- 서버 장애에 의존하지 않음 — 마지막으로 받은 데이터를 보여주고 앱이 죽지 않는 구조.

### 가격
**완전 무료. 구독·광고 없음.** (수익화 이전 MVP 단계 — 지금은 "오늘 뭐 볼지"를 잘 맞히는 것에만 집중.)

### 지금 한계 (솔직하게)
- 꿀잼지수의 실경기 적중률은 아직 누적·튜닝 중입니다. 초기엔 체감과 어긋나는 경기가 있을 수 있고, recap 데이터로 가중치를 계속 보정합니다.
- 푸시 알림·실시간 인앱 티커는 아직 없습니다(탭 재진입 시 갱신). 로컬 알림은 로드맵에 있습니다.
- iOS는 아직, 현재 Android(APK) 중심.

### 왜 지금, 왜 이거
경쟁자(네이버·KBO 공식앱·커뮤니티)는 데이터·여론은 주지만 **"한 경기를 골라주는" 큐레이션이 없습니다.** 우리는 그 한 가지를 빠르고 가볍게, 서버 없이 합니다. 전환 비용도 낮습니다 — 깔고 팀만 고르면 오늘 당장 씁니다.

### 유래한 고객 pain + 근거 인용

고객 페르소나 시뮬(`persuasion-data/runs/kbo-core-fan-01_20260624_130750/`)에서 코어 한화 팬(keyman)이 **설치는 하겠으나 절친에게 전파(추천)는 거부**하며 drop했다. 최종 판정 = **실패(keyman_drop, confidence 60)**. 결정적 drop 사유는 **꿀잼지수 적중률 미검증** — 이 앱 신뢰의 단일 기준인 정확도에 대한 객관 근거가 하나도 제시되지 않았다는 것.

- 키맨 발화(`01_keyman_initial.md` 걱정/의문점):

- report.md 페르소나 보정 힌트(결정적):

또한 report 개선 #5(재방문 후킹: "어제 적중 회고로 매일 재방문 습관화")와도 직결 — 누적 트랙레코드는 **신뢰 + retention** 두 마리를 잡는다.

### 구현 스케치

**현재 구현 상태(검증됨)**: `data-pipeline/build.mjs` L474-490이 이미 종료(FINAL) 경기마다 박스스코어(점수차/연장/끝내기/총득점)로 "실제 꿀잼" actual을 계산하고, 사전 예측 honjam.score와 비교해 `recap = { actual, verdict }`를 산출한다(verdict = '기대 이상' / '예측 적중' / '기대 이하'). 앱(`GameCard.tsx`, `Today.tsx`)은 이를 **당일 한정**으로만 표시한다. 갭: games.json은 오늘 경기만 담고 매 5분 덮어써져, 날짜를 넘는 누적 적중 수치가 없다(로드맵 docs/roadmap.md C의 미완 TODO와 동일).

1. **`build.mjs`**: FINAL 경기의 per-game recap을 `data-pipeline/output/recap-history.json`(append-only, gameId로 dedup)에 누적. 각 레코드 `{date, gameId, pred, actual, verdict}`. 빌드 끝에 rolling aggregate 계산(최근 N경기/일 중 verdict=='예측 적중' 비율 = 적중률, '기대 이상'은 별도 보너스로 분리 표기). 파일 헤더에 `{hitRate, sampleSize, window}` 기록.
2. **앱**: `{hitRate, sampleSize}`를 읽어 Today 상단 또는 설정에 신뢰 배지 1줄 표시. 표본 부족 시 수치 대신 '집계 중'.
3. **정의 투명성**: "예측 꿀잼지수가 실제 체감과 ±10 안에 든 비율"이라는 정의를 배지 옆에 1줄 병기.

**인간 개입 지점**: 설계/구현은 AI가 CLI에서 완결 가능(build.mjs JS 편집 + app TSX 배지 1개 + 타입 추가). 배포는 표준 절차 — 파이프라인 변경은 origin/main push로 라이브 반영, 앱 변경이므로 APK 재빌드 필요. 적중률 표본은 실제 며칠 운영하며 누적돼야 의미 있는 수치(첫날은 '집계 중'). 이는 "운영 시간"이지 인간 개입이 아님.

### CTO 승인 조건부 조건 (tech-critic-lead, 승인 confidence 78)

1. **표본 게이트 필수.** `sampleSize`가 임계치 미만이면 수치 노출 금지, '집계 중'으로만 표기. 과장은 정확도-민감 페르소나에게 즉시 삭제 트리거(report L38). 첫 며칠은 반드시 '집계 중'.
2. **정의 투명성 1줄 병기 필수.** "예측 ±10 이내 비율" 정의를 배지 옆에 표기. verdict 정의(`build.mjs` L485-488)상 '예측 적중'은 actual이 pred±10인 구간이므로, 적중률에 '기대 이상'을 합산하지 말 것 — '기대 이상'은 별도 보너스로 분리.
3. **append-only 멱등성 검증.** gameId dedup이 5분 주기 재실행·재빌드에서 중복/유실 없이 동작해야 함(파이프라인이 같은 FINAL 경기를 여러 번 봄). dedup이 깨지면 적중률 수치가 오염되어 기능 가치가 역전됨 — 구현 시 최우선 테스트 대상.
4. **honjam freeze 정합성.** recap의 pred는 반드시 '경기 전 고정값'(`build.mjs` L457 prevHonjam freeze 경로)을 써야 함. 사후 재계산 값으로 적중률을 매기면 자기충족적 부정직. honjam이 이미 freeze되므로 honjam.score를 그대로 누적하면 정합하나, 첫 실행에 prevHonjam이 없던 경기는 누적에서 제외할 것.

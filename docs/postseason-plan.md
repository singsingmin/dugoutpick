# 포스트시즌(가을야구) 화면 설계 — 오늘야구각

> **성격:** 개발자 의사결정 문서. 6개 버킷 요구사항 확정안. 구현 착수 전 스펙 박제.
> **상태:** 설계 확정(2026-07-11 논의). **구현 미착수** — 착수 시점 목표는 2026 KBO 포스트시즌(대략 10월) 이전.
> **착수 선행(필수):** ✅ **API 스파이크 완료**(2026-07-11, 2025 실데이터) — 6번 참조. srId 매핑 정정(WC=4·준PO=3·PO=5·KS=7), 시리즈스코어는 누적 도출 확정. 이제 로직·테스트 구현 가능.
> **관련:** [roadmap.md](roadmap.md) A '포스트시즌 화면' · [adr.md](adr.md) ADR-003(엔드포인트)/ADR-004(꿀잼지수) · [prediction-league-design.md](prediction-league-design.md).
> **표기:** MVP = 이번 시즌 목표 · 후속 = 백로그.

---

## 0. 배경 · 성격

- 정규시즌과 결정적으로 다른 점: **하루 보통 1경기**, 전 경기가 고강도, 단기전이라 순위·폼의 의미가 달라짐.
- 그래서 꿀잼지수의 역할이 바뀐다: 정규시즌은 "여러 경기 중 뭐가 제일 재밌나(변별)"지만, 포스트시즌은 **"오늘 이 경기가 얼마나 큰 판이냐(기대치)"**.

### KBO 가을야구 구조 (스텝래더)

```
 WC   4위 ── vs ── 5위       최대 2경기, 4위 1승 어드밴티지(5위는 2연승해야 진출)
              │(승자)
준PO  3위 ── vs ── ▲         5전 3선승
              │(승자)
 PO   2위 ── vs ── ▲         5전 3선승
              │(승자)
 KS   1위 ── vs ── ▲   → 우승  7전 4선승
```

## 1. 포스트시즌 꿀잼지수 보정 (확정)

**정규시즌 공식과 완전 분리.** 정규시즌은 9요소 가중합 + 로지스틱 보정(`computeHonjam`, `data-pipeline/build.mjs`). 포스트시즌은 별도 함수 `computePostseasonHonjam`.

- **base 70 · 순수 가산 · 로지스틱 없음**(로지스틱은 "기본 70" 의도와 충돌).
- **clamp [68, 100]** — 포스트시즌은 최저도 정규 명경기급으로 바닥을 깐다.

| 요소 | 가산 | 비고 |
|---|---|---|
| **라운드** | WC +0 · 준PO +2 · PO +4 · **KS +7** | 뒤 라운드일수록 무게 |
| **승부처**(시리즈상황 ∪ 탈락위기) | 최종차전 **+18** / 엘리미네이션·클린치 **+12** / 그 외 팽팽함 비례 **0~+8** | 가장 큰 지렛대 |
| **선발** | **0~+6** | 양 선발 aceness(ERA) — 기존 로직 재활용 |
| **직전경기 흐름** | **0~+4** | **시리즈 내 직전 경기**가 역전/끝내기/연장/1점차면 가산 |

- **승부처 판정 규칙**
  - 최종차전 = 5전제 2-2 후 5차전, 7전제 3-3 후 최종전.
  - 엘리미네이션 = 지면 탈락하는 팀이 있는 경기. 클린치 = 이기면 진출/우승 확정.
  - **WC 5위팀은 매 경기 win-or-go-home** → 자동 엘리미네이션 취급.
  - '시리즈 상황'과 '탈락 위기'는 실질 중복이라 **하나의 승부처 지렛대**로 통합(스코어 + 시리즈 포맷으로 판정).
- 스케일 감각: 라운드 초반 원사이드 경기 ≈ 70, 한국시리즈 최종전 ≈ 100.
- **데이터 의존:** 승부처·직전경기 흐름 모두 **시리즈 스코어**가 필요 → 6번(context 모델) 선행.

## 2. 시리즈 현황 카드 (확정)

- **위치:** 오늘경기 탭 **상단**(예측카드 위). 포스트시즌엔 하루 1경기라 이 카드 + 그 경기 카드가 사실상 히어로.
- **구성:**

```
┌─────────────────────────────┐
│  한국시리즈 · 3차전          │  라운드명 + 차전
│  [LG] 2 ─ 1 [KT]             │  시리즈 스코어(로고 + 승수)
│  🔥 LG 이기면 매치포인트      │  승부처/진출·탈락 맥락 한 줄
│                       대진표 ▾ │  ← 탭하면 브래킷 바텀시트(5번)
└─────────────────────────────┘
```

- **라운드명:** 와일드카드 결정전 / 준플레이오프 / 플레이오프 / 한국시리즈.
- **차전:** "N차전" (`VS_GAME_CN`).
- **맥락 한 줄**(상황별 자동):
  - 매치포인트: "○○ 이기면 진출/우승"
  - 벼랑끝: "○○ 지면 탈락"
  - 최종차전: "운명의 최종전"
  - WC 특수: "4위 ○○ 1승 어드밴티지 · 5위 △△ 2연승 필요"
- **확정 결정:**
  1. 포스트시즌엔 기존 **'오늘의 추천' 히어로 + 예측카드 숨김** → 현황 카드 + 경기 카드만.
  2. 오늘 **홈팀/구장** 맥락 표기 포함(홈어드밴티지).
  3. 1차전(0-0)은 스코어 대신 **"시리즈 개막"** 문구.

## 3. 예측리그 연동 (확정)

- 기존 "오늘 제일 재밌을 경기" 예측은 하루 1경기라 무의미 → **MVP에선 포스트시즌 기간 예측 비활성**.
- 2번 결정과 자동 연동: PO 땐 예측카드 자체가 안 뜸.
- **후속(백로그):** **포스트시즌 특별 예측**(예: 시리즈 승자 · 시리즈 MVP · 오늘 결승타 주인공 등)으로 확장 검토. [prediction-league-design.md](prediction-league-design.md) 연계.

## 4. 내 팀 컨텍스트 (확정)

내 팀 화면(`MyTeam`) 상단(오늘 경기 섹션 자리)을 '가을야구 모드'로 전환. **상태 4분기:**

| 상태 | 조건 | 표시 예 |
|---|---|---|
| **진출(대기)** | 상위 시드라 시리즈 아직 시작 전 | "○○ 준PO 대기 중 (10/8 시작)" |
| **진행 중** | 시리즈 진행 중 | "○○ 플레이오프 1승 1패 · 오늘 3차전" (현황 카드 재활용) |
| **탈락** | 가을야구 진출했으나 탈락 | "○○ 가을야구 종료 — 준PO에서 아쉬운 탈락" + 격려 |
| **진출 실패** | 정규시즌 6위 이하 | "○○ 올해 가을야구는 다음 기회에" |

## 5. 브래킷 (확정)

- **형태:** KBO 계단식(스텝래더)을 반영한 **8비트 톤 세로 스텝래더**.
  - 끝난 라운드 = 승자 표시, 현재 라운드 = 하이라이트, 미정 슬롯 = "?".
  - 내 팀 강조.
- **위치(UX 확정):** **시리즈 현황 카드 탭 → 브래킷 바텀시트**.
  - 근거: 기본 화면 깔끔 유지(브래킷은 매일 볼 필요 없고 라운드 바뀔 때만 갱신) · 카드가 이미 최상단 포커스라 드릴다운이 직관적(progressive disclosure) · 별도 화면보다 발견성↑ · **바텀시트는 앱 기존 패턴**(라커룸 거래내역)이라 학습비용 0.
  - 카드 우측에 "대진표 ▾" 힌트.

## 6. 자동 감지 · 데이터 (확정 + 선행 검증 필요)

### postseasonContext 모델

```
{
  active,                       // 포스트시즌 기간인가
  round,                        // WC | 준PO | PO | KS
  roundName,                    // GAME_SC_NM 기반 표시명
  gameNo,                       // VS_GAME_CN, N차전
  seriesFormat,                 // WC 2 / 준PO·PO 5 / KS 7
  high, low,                    // 상위 시드 / 하위 시드 팀 코드
  seriesScore: { [code]: 승 },  // 시리즈 스코어
  wcAdvantage,                  // WC 4위 1승 어드밴티지 플래그
  matchpoint, elimination,      // 스코어+포맷에서 파생
}
```

### ✅ API 스파이크 검증 완료 (2026-07-11, 2025 시즌 실데이터)

`GetKboGameList`(POST, `body=leId=1&srId=${srId}&date=${date}`)를 2025 포스트시즌 날짜로 호출해 실제 필드 확인. **로드맵 메모의 srId 매핑은 틀렸었음** — 실측값으로 정정:

| 라운드 | **srId(실측)** | GAME_SC_NM 예 | 비고 |
|---|---|---|---|
| 정규 | 0 | "정규경기" | |
| **WC** | **4** | "WC1","WC2" | 로드맵은 3이라 했으나 실제 4 |
| **준PO** | **3** | "준PO3" | |
| **PO** | **5** | "PO1" | 로드맵은 3이라 했으나 실제 5 |
| **KS** | **7** | "KS1"~"KS5" | |

- **라운드+차전 판정:** `GAME_SC_NM` 문자열이 라운드명+차전을 직접 인코딩(`WC2`, `준PO3`, `PO1`, `KS5`). 파싱 정규식 `/(WC|준PO|PO|KS)(\d+)/` — **준PO를 PO보다 먼저 매칭**해야 함(부분문자열). `VS_GAME_CN`(정수)도 차전과 일치.
- **시리즈 스코어:** ❌ API 미제공 확인. → **끝난 경기 결과 누적으로 도출**(검증됨). 각 경기 `T_SCORE_CN`(원정)·`B_SCORE_CN`(홈)·`AWAY_NM`/`HOME_NM`, `GAME_RESULT_CK=1`(종료). **홈/원정이 차전마다 바뀌므로 팀명 기준으로 누적**(2025 KS 재현 LG 4-1 확인). `matchpoint`/`elimination`은 스코어+포맷에서 파생.
- **시드/순위:** `T_RANK_NO`/`B_RANK_NO`/`T_GROUP_SC`/`B_GROUP_SC` 전부 **null** → 이 엔드포인트로 못 구함. → **정규시즌 최종 순위(standings.json)에서 팀 코드로 조회**해 상위/하위 시드 판정.
- **경기 종료 상태:** `GAME_STATE_SC="3"` = 종료.
- **잔여 리스크(ADR-003):** 비공식 엔드포인트라 2026 시즌에 필드/동작이 바뀔 수 있음 → 착수 시 당해 시즌 첫 포스트시즌 경기로 재확인 권장. 그러나 2025 구조가 확인됐으므로 로직·테스트는 지금 구현 가능.

## 구현 순서 (제안)

1. **[선행] API 스파이크** — 6번 필드·시리즈스코어 검증. 여기서 막히면 나머지 전부 블록.
2. **6번** postseasonContext 파이프라인(감지 + 스코어 누적).
3. **1번** `computePostseasonHonjam`(context 의존).
4. **2번** 시리즈 현황 카드 + PO 모드(추천·예측 숨김).
5. **4번** 내 팀 컨텍스트 4분기.
6. **5번** 브래킷 바텀시트.
7. **3번** 예측 비활성은 2번에 흡수(별도 작업 없음). 특별 예측은 후속.

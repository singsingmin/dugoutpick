# 페르소나 보정 힌트

- **파일: `01_keyman_initial.md` — `decision_authority = full`인데 decision이 drop으로 수렴한 점에 주의.**
  관찰: full authority(자기 폰에 자기가 설치)는 본래 "설치 결정"에 마찰이 없어야 한다. 그런데 세션의 drop 논리는 사실상 "설치는 하겠지만 **절친에게 추천(전파)은 안 한다**"는 *전파 판단*이며, 이를 `decision = drop`으로 환원했다. 발화 *"나 혼자 깔아보는 건 한다 … 들고 가 설득할 단계는 아직 아니다"*. → 이 페르소나에서 keyman의 decision 축은 "도입(install)"이 아니라 "전파(advocacy)"에 가깝다. 향후 캘리브레이션 시 **install 결정과 advocacy 결정을 분리**하지 않으면, full authority인데도 항상 drop으로 비관 수렴할 수 있다.

- **파일: `01_keyman_initial.md` — `unknown` 필드(`sh-casual-friend.trust_with_keyman: unknown`)의 간접 영향.**
  관찰: 캐주얼 지인의 trust가 unknown인 상태에서, 키맨은 전파 라인 전체(절친→캐주얼)의 불확실성을 drop 사유로 흡수했다. unknown 자체를 직접 인용하진 않았으나, 전파 단계 자체를 보류하는 보수적 판단으로 이어진 정황이 있다. → 캐주얼 지인 trust에 중립 기본값(예: 코어팬 추천 시 50)을 부여하면 비관 편향이 완화되는지 점검 권장.

- **파일: `value_proposition.md` (입력) — "지금 한계" 자기 고백이 reject_trigger와 1:1로 충돌.**
  관찰: 가치제안 54행이 *"실경기 적중률은 아직 누적·튜닝 중 … 체감과 어긋나는 경기가 있을 수 있음"*이라고 명시했고, 키맨의 reject_trigger가 정확히 "점수가 실제 재미와 어긋남"이다. 솔직한 한계 고백이 이 특정 페르소나에게는 **결정적 drop 유발자**로 작동했다. → 페르소나 자체 보정은 불필요(자연스러운 반응)하나, 시뮬 해석 시 "정직한 한계 명시가 정확도-민감 페르소나에서 과대 페널티로 작동"하는 점을 유의. 동일 가치제안이라도 적중 근거 1줄 추가 시 결과가 뒤집힐 가능성이 높음(→ 가치제안 개선 포인트 1과 연동).
